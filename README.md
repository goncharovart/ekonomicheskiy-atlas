# Экономический атлас муниципалитетов: типы потребления по безналичным тратам 2023–2024

Конкурс СберИндекса, трек «Кластеризация». Автор — Артур Гончаров.

Муниципальные образования (МО) России делятся на типы местной экономики по структуре безналичных трат жителей. Затем прослеживаем, как МО переходят между типами месяц за месяцем. Узлы сети — МО, рёбра — «чьи траты движутся вместе», атрибуты — доли трат, уровень трат и доступность рынков. Восемь методов кластеризации (пять базовых — k-means, Ward, GMM, Leiden, спектральная — и три метода членов жюри) сравниваются по шести индексам качества.

Каждый шаг опирается на работы членов жюри:
- **Шалилех и Миркин** — KEFRiN и CANUS на сети с атрибутами (отчёт, §4.6–4.7), итоговая типология — KEFRiN;
- **Алескеров и Мячин** — порядково-инвариантная паттерн-кластеризация (§4.8), и тот же Алескеров — пороговое агрегирование шести индексов, основной вариант рейтинга при выборе метода (§6.2, §6.4);
- **Кузнецов** — описание типов формальными понятиями с оценкой их устойчивости (§8.5).

- **Методологический отчёт:** [reports/ОТЧЁТ.md](reports/ОТЧЁТ.md) (PDF: [reports/ОТЧЁТ.pdf](reports/ОТЧЁТ.pdf))
- **Лендинг** с картой типов по месяцам, переходами и профилями: https://goncharovart.github.io/ekonomicheskiy-atlas/ (исходник [site/index.html](site/index.html) открывается и прямо из файла, без сервера; печатная версия: [site/landing.pdf](site/landing.pdf))

## Путь от данных к типам

**траты МО по месяцам → признаки МО → сеть МО → восемь методов кластеризации → шесть индексов качества против случайного разбиения → итоговая типология → переходы МО между типами → описание типов**

## Главный результат

2 016 МО с полными рядами за 24 месяца (январь 2023 — декабрь 2024) делятся на **7 типов**. Типологию даёт **KEFRiN** Шалилеха и Миркина (k-means на атрибутах МО вместе со строками графа). При общем $K=7$ методы сравниваются в восьми вариантах рейтинга по шести индексам (SW, CH, S_Dbw, AVI, AVU, MQ): пороговое агрегирование Алескерова и Борда, с AVU и без, на сквозных признаках и по медиане месяцев. KEFRiN — единственный метод, который во всех восьми вариантах стоит на 1-м или 2-м месте, и самый устойчивый по месяцам: МО проводит в модальном типе 77 % месяцев, у CANUS 73 %, у Ward 59 %. Первая она не везде: с AVU на сквозных первым идёт Ward (его место держится на одном $z_{AVU}$), по медиане месяцев — k-means (отчёт, §6.4).

| Тип | Название | МО |
|---|---|---|
| 0 | Сельские районы с самыми низкими тратами: продукты выше среднего | 377 |
| 1 | Районы и малые города: транспорт и здоровье ниже среднего | 342 |
| 2 | Сельские районы с самой высокой долей маркетплейсов | 357 |
| 3 | Москва, Подмосковье и соседние областные центры: самые высокие траты и доступность рынков | 251 |
| 4 | Север и Восток: высокие траты при худшей доступности рынков | 269 |
| 5 | Петербург и крупные города: общепит и транспорт выше среднего | 277 |
| 6 | Районы Сибири: транспорт выше среднего, доступность рынков низкая | 143 |

Тип МО здесь — самый частый за 24 месяца (`outputs/interpret/mo_types.csv`). Росстат в кластеризацию не входил, но типы по нему различаются сильно: зарплата ($\eta^2_H \approx 0{,}55$), население (0,44), доля занятых в торговле (0,33). Описания типов — `outputs/types.csv`, профили — `outputs/interpret/`, переходы — `outputs/dynamics/`.

## Установка

Python 3.12, CPU без GPU. Из корня репозитория:

```
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt     # Linux и macOS: .venv/bin/python
```

`requirements.txt` закрепляет точные версии; `torch` ставится в сборке для CPU с индекса PyTorch (строка `--extra-index-url` в файле). Для скачивания архивов нужен `bsdtar` (в Windows это штатный `tar.exe`).

## Запуск одной командой

```
.venv/Scripts/python.exe -X utf8 scripts/run_all.py
```

Шаги по порядку: `download_data → build_panel → fetch_external → run_baseline → run_jury → run_compare → run_interpret → run_dynamics → check_mobility → prepare_geo → build_site`. После каждого шага проверяется, что он записал свои файлы; если нет, конвейер останавливается. Флаги:

- `--skip-download` — данные уже в `data/raw`;
- `--quick` — проверка, что всё запускается: тяжёлые шаги идут в укороченном режиме и пишут в `outputs/quick/`, полные результаты не трогают;
- `--fresh` — пересчитать KEFRiN и CANUS в `run_compare` и бутстрэп в `run_dynamics` без кэша (кэш лежит в `outputs/`).

Число параллельных воркеров задаёт `n_jobs` в `configs/baseline.yaml` и `configs/compare.yaml` (по умолчанию 3, каждый занимает около 0,5 ГБ памяти). Перед тяжёлыми шагами `run_all.py` ждёт, пока освободится хотя бы 2 ГБ.

Каждый шаг можно запустить и отдельно: `scripts/<шаг>.py`, у каждого в шапке описаны входы и выходы. PDF отчёта и лендинга пересобирает `scripts/build_pdf.py` (нужен Chrome).

Время на CPU (Intel Core i5-12400F, 12 потоков, без GPU, `n_jobs: 3`; замер 30.09.2026 на машине, занятой и другими программами, поэтому разброс):

| Шаг | Время |
|---|---|
| `download_data` — всё с нуля (архивы Сбера, API СберИндекса, три таблицы Росстата по HTTP Range) | 62 с |
| `build_panel` | 18–40 с |
| `fetch_external` — клон KEFRiN и CANUS с нуля | 24 с |
| `run_baseline` | 131–153 с |
| `run_jury` | 395–870 с |
| `run_compare` с кэшем меток KEFRiN и CANUS / без кэша (`--fresh`) | 208 с / 1 195 с |
| `run_interpret` | 2–3 с |
| `check_mobility` (внешняя проверка типов индексом мобильности СберИндекса, 274 МО СЗФО) | 1–2 с |
| `run_dynamics` с кэшем бутстрэпа / без кэша (`--fresh`, 100 подвыборок × KEFRiN) | 4–5 с / 555 с |
| `prepare_geo` + `build_site` | 3–4 с |
| **весь конвейер `run_all.py --skip-download`**, кэши на месте | **1 164 с (19 мин)** |
| весь конвейер `run_all.py --skip-download --fresh`, без кэшей | 2 304 с (38 мин) |
| `run_all.py --skip-download --quick` | 77–108 с |

Ward, GMM и спектральная добавлены после замера всего конвейера и времени без кэша: `run_compare` с кэшем вырос с 114 до 208 с, остальные шаги они не затрагивают.

Воспроизводимость: seed 42 везде, коммиты чужого кода закреплены, контрольные суммы скачанных файлов — в `data/raw/SHA256SUMS` (он в репозитории; повторное скачивание 30.09 совпало со всеми 14 суммами). Повторные прогоны `run_all.py --skip-download`, с кэшами и без них (`--fresh`), при 12 и 3 воркерах воспроизвели байт в байт панель, все метки, индексы, рейтинги, профили, динамику и данные сайта. Отличаются только поля с временем счёта и датой сборки, а у пересчитанного кэша меток KEFRiN и CANUS — порядок строк (содержание то же). Метки Ward, GMM и спектральной, пересчитанные отдельным процессом, совпали с сохранёнными во всех 219 разбиениях.
